Ultharness for Mac

NEWT AND MISSIONS
Quit older copies of Newtv1 and Ultharness first. Open the combined app,
click Talk with Newt, or press Option-Space. Say "start mission build a client
website". Choose a project and start the run. Select the saved settings option
to start future aims by voice alone. Use "mission status" or "stop mission".
The optional browser extension and installer are in Extras/Browser Integration.

INSTALL
Drag Ultharness.app onto Applications, then open it from Applications.
This build is for Apple Silicon Macs running macOS 14 or later.

WHAT IS INCLUDED
The native window, dashboard, local server, Node.js, npm and npx are bundled.
You do not need a separate Node installation for the dashboard or npm checks.
Client project dependencies and external tools must still be available.
Your API keys, task database, source folders, and model weights are not included.

YOUR WORKSPACE
If the same browser version is running at http://127.0.0.1:4310, the app
connects to it, preserving that workspace. Quitting the Mac app leaves that
separately started server running.

Otherwise (including an older browser server) the Mac app starts its own local server and stores data in:
  ~/Library/Application Support/Ultharness/workspace

Use File > Connect Project Folder to choose a project. The standalone app's
initial project is your Documents folder. Its server and schedules stop when
you quit. Existing project-folder databases are not moved or modified.

MODEL SERVICES
Codex, Claude, OmniRoute, Ollama, their sign-ins, and local model weights are
separate installations. The Model Services menu can start installed OmniRoute
or Ollama. Services started by this app stop when the app quits. Services that
were already running stay running.

For a gateway key that survives standalone app restarts, create:
  ~/Library/Application Support/Ultharness/settings.env
with OMNIROUTE_API_KEY and, optionally, OMNIROUTE_BASE_URL. Keep that file
private. The key form in Model routing otherwise stores keys for the session.
The running-browser connection uses that server's existing settings instead.

SIGNING
This is an ad-hoc signed local build, not an Apple-notarized distribution.
macOS may require explicit approval to open a downloaded copy. No security
settings are changed by this installer.

TROUBLESHOOTING
File > Open Desktop Log shows startup errors.
File > Open App Data Folder opens the standalone app's settings and data.

CLIENT DELIVERY
Connect a dedicated client folder, then open Client deliveries > New client brief.
Add the brief, acceptance criteria, required files and verification script names.
Choose agents, connections, a model route and a repair limit. Save the draft,
review the scope, and approve the bounded build/check/review/repair cycle.
Passing work waits for your acceptance. Publication is a separate action.
Connections can be reference links/files or separately configured MCP read tools.
A saved reference is not an authenticated service connection.

ONE AIM, LIVE WORK
Click Start with an aim, enter the goal and references, choose a project folder,
and Start & watch live. The app plans standards, builds, verifies, reviews and
repairs within your selected limit. Live workspace shows actual output.
Live site preview reloads static/built HTML as files change; it does not start
framework development servers. You can stop the cycle at any time. Passing
work waits for your final acceptance. Account and tool availability still matter.
